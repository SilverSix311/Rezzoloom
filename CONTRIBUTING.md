# Contributing

Rezzoloom is in planning. Read the product brief, architecture proposal, and open decisions before proposing code.

For a planning change, explain the problem, proposed decision, tradeoffs, and evidence. Label assumptions and link current official documentation for integration claims. Use the planning issue template to keep unresolved questions concrete.

Do not include credentials, copyrighted show media, or private audience logs. Licensing is undecided; settle it before accepting substantial external code contributions.

For this documentation-only stage, verify relative Markdown links and run `git diff --check`. Runtime commands and automated application tests will be documented after a stack is chosen.
